<h1 align='center'> Atividade 1 - Cometário Texto 1 </h1>

> Este trecho tem como objetivo principal comparar engenharia de software e outras engenharias.
O texto aponta que, assim como engenharias de aeronáutica, mecânica, etc, o objetivo da profissão seria a criação de algo, nesse caso, um software.
Entretanto, o parágrafo também aponta uma falta de regulamentação da profissão, argumentando que não segue métodos exatos para se alcançar o objetivo, como cálculos, diferentemente de outras engenharias, e utiliza um padrão muito mais flexível.
Colocando em perspectiva na realidade, para exercer a profissão, não é necessário um diploma ou formação, mas somente o conhecimento, assim como outras profissões da área de tecnologia e, durante a execução da mesma, não são seguidos padrões estritos e controlados.

<h1 align='center'>Atividade 2 - Comentário Texto 2</h1>

> Este trecho tenta definir o que é a engenharia de software, apontando que não somente a parte do desenvolvimento, mas a manutenção do código e os processor utilizados também são objetos de estudos.
Como algo mais abrangente, o texto idealiza a engenharia de software como a aplicação de um programa ao longo do tempo. Também aponta que faz parte da profissão estudar e implementar métodos para estender a vida útil de um software. No que se diz respeito a este tópico, é argumentado que há 3 princípios fundamentais para se conquistar o objetivo: 1 - Atualizações, isto é, manter o produto atualizado para com as mudanças que a tecnologia percorre; 2 - Crescimento, ou seja, aumentar a escala que a organização abrange; 3 - Custos e Trocas, que significa como uma organização toma suas decisões em relação aos tópicos anteriores.

<h1 align='center'>Atividade 3 - Exemplos Trade-Offs</h1>

>Trade-Offs é um conceito de Engenharia de Software que retrata o dimensionamento de um atributo do software.
Por exemplo, um software que consegue aguentar 1 milhão de acessos por dia é excelente, entretanto seu custo será elevado, o intuito dos Trade-Offs são analisar como o software será utilizado e dimensionar suas especificações de acordo com o custo-benefício.
Um exemplo de Trade-Off é a responsividade. Em um aplicativo web, a resposividade é essencial, pois diferentes usuário acessarão de diferentes dispositivos, porém em um sistema embarcado é quase irrelevante, pois o software só será executado em um tipo de tela.
Outro exemplo seria o escalonamento. No sistema de uma academia de bairro, que faz o check-in e check-out, além de armazenar os treinos dos alunos, terá em média 50 usuários conectados, então não será necessário escalonar este software para que aguente 100 mil usuário conectados ao mesmo tempo, assim reduzindo o custo do programa.
